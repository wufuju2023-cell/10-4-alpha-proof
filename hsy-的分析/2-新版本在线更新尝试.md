一、Online-v2 已完成的改进

原来的 `-rΔ + βΔ²` 被替换为版本绑定的 clipped PPO：

ρₜ = exp(logπθ(aₜ|s) - logπ_old(aₜ|s))

Lppo = -min(ρₜA, clip(ρₜ,1-ε,1+ε)A)

并实现：

- 一个 rollout wave 内冻结行为策略 π_old；
- 保存逐 token old_logprob 和 policy_version；
- 拒绝混入其他策略版本的陈旧样本；
- batch 按独立 problem_id 计数，而不是按 event 数；
- advantage 只比较同一 Lean state 下具有搜索证据的动作；
- 没有可比较动作时 advantage 自动为 0；
- 不把 timeout 的失败奖励广播给此前所有 tactic；
- 使用动作位置上的全词表 KL，而不是 βΔ² 伪装的 KL；
- clipped PPO、梯度裁剪、KL 硬门和自适应 β；
- canary 拒绝或数值异常时，完整恢复模型、optimizer、更新计数和 RNG；
- 保留官方 64 桶剩余步数目标，终局奖励不冒充 value target。

二、官方 CE + DeepSeek V4.1 蒸馏已完成

准确地说，这是：

“学生 on-policy 状态分布上的教师蒸馏”

流程为：

当前学生/MCTS 产生实际访问的 Lean state
→ DeepSeek 和学生分别提出 tactic
→ Lean 执行候选
→ 搜索确认动作是否位于完整、严格验证的证明或反证路径
→ 只有验证成功路径上的 state–tactic 对进入官方 CE replay

外部教师只负责扩展候选，不负责判断数学正确性。

代码明确区分了：

- Lean 能执行一步；
- 动作最终位于完整验证证明路径。

前者不会自动成为 CE 标签，只有后者才能进入训练。

DeepSeek 与学生的 tokenizer 不同，因此没有做虚假的跨 tokenizer logits KL，而是对经过 Lean 和搜索验证的 tactic 文本做 sequence-level CE。接口兼容 DeepSeek/OpenAI-compatible 服务，凭据只从环境变量读取，不进入配置、回执或日志。
