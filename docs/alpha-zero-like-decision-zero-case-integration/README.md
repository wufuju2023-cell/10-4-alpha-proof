## 0. TL;DR

- **Decision-Zero（DZ）** 指：把一个数学/代码/Lean 子问题**编译成一个廉价可模拟的有限 MDP**——
  状态是固定离散格局（如 `{0,1}^N` 的 bit 点，N<1000），动作是"选一个点改一个坐标"，
  多轮推进，奖励形式化可计算，整任务等价于多轮决策；用 **AlphaZero 式 MCTS + (p,v) 网络 +
  交叉熵策略迭代 + 自对弈** 求解。
- 这与"选择题"（一次性排序/分类，输入还是 token 串）有本质差异：DZ 必须具备
  **同构动作集、廉价模拟器、形式化奖励、可自对弈** 四条；缺一条就退化为弱形态。
- Lean 侧的接合点是**证书**：不信任网络输出；DZ 只负责"找到有限证书"（赋值/迹/策略表），
  Lean 内核负责"把证书变成定理"（`decide`/`native_decide`/`checker_sound` 一族证一次）。
- 可编译的正是"存在证书型"与"有限博弈型"数学；连续数学与无界量词嵌套仍然留给 AlphaProof。
- 与 AlphaProof 的整合 = **Extractor → DZ 训练/求解 → 证书编译 + 内核门 → dz 宏动作与触发学习**，
  两边共享 wave 数据但各自训练；DZ 侧可以完全自产数据（自对弈），成本量级远低于证明器波次。

## 1. 定义：什么是（以及不是）Decision-Zero

### 1.1 弱形态 vs 真形态

| | 弱形态（不是 DZ） | 真形态（DZ，本文对象） |
|---|---|---|
| 状态 | token 串 / 自由文本上下文 | 固定格局：`s ∈ {0,1}^N`（或小组合域） |
| 动作 | 从候选列表挑一个（排序/分类） | 同构的"选点"：改一个坐标（如某位 0→1） |
| 回合 | 一次性 | 多轮、状态转移、到终局 |
| 回报 | 最终对错，无轨迹结构 | 形式化奖励 `R(s)`，可逐步模拟 |
| 可自对弈 | 基本不能 | 可以（环境廉价、数据无限自产） |
| 学习形态 | 排序器 | value 模型 + MCTS + 策略迭代 |

> 此前讨论过的"前提选择头/族权重"属于**弱形态**（一次性、token 输入），有用但**不算 Decision-Zero**；
> 本文按真形态展开。

### 1.2 形式化定义

```text
DZ 任务 = (N, A, T, R, 回合制)
  状态    s ∈ {0,1}^N                       # bit 格局；N < 1000（固定）
  合法动作 A(s) ⊆ {(i, v) | i ∈ [N], v ∈ {0,1}}   # "选点 + 置值"；常带 legality mask
  转移    s' = T(s, a)                      # 确定性、廉价（可在 Lean 内直接执行）
  奖励    R(s) → {0,1} 或 {±1}              # 形式化、可计算
  终局    步数上限 ≤ N（构造型）或 2N（博弈型），或"证书完成"

求解目标：学习 p(a|s), v(s)，用 MCTS 搜索，使自对弈收敛到高奖励终局；
          终局产物＝证书，由 Lean 校验器转化为定理。
```

要点：

- **单调构造**（只允许 0→1）：任务图是 DAG，不需要在状态层面回溯（回溯由搜索树承担）；
  任何到达的终局天然就是"证书本体"。
- **合法性用 mask 表达**（如着色：N = 单元数 × 颜色数，mask 限制"每单元至多一色"），
  不要把约束塞进奖励里，否则 MCTS 会被大量非法分支稀释。
- **奖励尽量终局化**。若需密集化，只用 potential-based shaping（策略不变性可证），别用会改变最优策略的启发式。

### 1.3 两种标准形态

1. **构造型（单玩家）**：单调置位，终局 = 证书，奖励 = 校验函数。
   覆盖"∃ 有限证书"的命题：`∃ x ∈ {0,1}^N, P(x)`。
2. **博弈型（双玩家）**：双方交替选点（各自的位域），终局判胜负，value 用当前玩家视角。
   覆盖 `∀ 对手走法, ∃ 我方走法` 的有限策略命题——这正是 AlphaZero 棋盘的形态。

对应到之前的外部资料[^1][^2]：SAT 的变量赋值（构造型）与棋类（博弈型）各有先例。

[^1]: 名称按记忆（细节以原文为准）：AlphaSAT（AlphaZero 解 CNF-SAT，2024）、Graph-Q-SAT（MCTS+RL 学变量赋值，2020）。
[^2]: MIP 学习分支（Gasse et al.）与 SAT 学习分支是同一类"有限决策 + 完备求解器 + 分支启发式"的范式。

## 2. 训练：AlphaZero 式自对弈 + 交叉熵策略迭代

### 2.1 网络 I/O（关键：输入不是 token）

```text
输入   : bit 格局 s（形状固定：N bits；可加 legality mask 与步数）
policy : 长度 N 的分布（选点概率；非法点 mask 掉）
value  : 标量（当前玩家/构造者的胜率或成功概率）
```

- 因为动作同构、状态定长，网络是普通 MLP/CNN/小 Transformer，**与文本模型无关**；
- 批推理廉价，可与 MCTS 线程池配套（我们的 `lmc` server 协议风格可直接借用）。

### 2.2 自对弈循环（与 AlphaZero 相同，策略损失用 CE）

```text
for each iteration:
  自对弈若干局：MCTS（p 先验 + v 评估 + UCB）→ 记录 (s, π_visit, z)
  训练：(p,q) 以 π_visit 为目标的交叉熵 + value 回归 MSE + 正则
  （可选）reanalyze / 数据回放
```

- 交叉熵对"访问分布"（不是 one-hot）就是本项目 E5 讨论的**软目标**在 DZ 里的自然形态；
- 这与项目现有的 CE/更新管线同构，可直接复用离线更新思想（数据自产、无 GPU 大模型）。

### 2.3 证书与内核门

终局 → 证书对象（bit 向量 / 迹 / 策略表）→ Lean 侧：

```lean
-- 目标形态（构造型）：∃ x : Fin N → Bool, P x
refine ⟨cert, ?_⟩
decide            -- 或 native_decide / 应用一族证的 checker_sound
```

**DZ 的任何输出都必须过内核门**；失败即回退 AlphaProof 常规搜索。安全性与 AlphaProof 的 strict replay 同规格。

## 3. 哪些 math/Lean/code 情形可编译成 DZ

| 类别 | Lean 里的形态 | bit 编码 | 奖励/终局 | 证书 |
|---|---|---|---|---|
| SAT / CSP | 布尔变元集合上的满足性问题 | 变量赋值位（三元用两位+mask） | 全约束满足 | 赋值 |
| 图证书 | 独立集/团/匹配/支配集/着色 | 顶点（或 单元×颜色）位 | 邻接约束检查 | 位向量 |
| F₂ 线代 | `A x = b`（GF(2)） | `x` 的位 | 计算 `Ax` 比对 | `x` |
| 有限博弈 | IMO 风博弈题：∃ 必胜策略 | 两方各自位域，交替 | 终局规则判定 | 策略表 |
| Nim / SG 类 | 局面 P/N、策略正确性 | 堆大小/动作索引位 | 走子合法性+终局 | 策略表 |
| 有限自动机 | 接受串/同步词等 | 转移选取的位序列 | 状态机运行结束判定 | 迹 |
| 有界模型检验 | 有限状态程序 BMC | 程序状态+输入位 | 断言违反 | 迹 |
| 小参数枚举 | `∃ n < K, P n` | n 的二进制位 | `P n` 计算 | n |
| 反例搜索 | `¬(∀ x ∈ S, P x)` | x 的位 | `¬P(x)` | x |

不适合：连续数学（分析/测度/拓扑）、无界量词嵌套的大定理、证书不是有限对象的命题——这些仍属 AlphaProof 领域。

## 4. 与 AlphaProof 的整合架构

```text
        Lean goal（文本、无限动作空间）                    DZ（bit 格局、有限动作）
                │                                            │
   ①Extractor  │ 把 goal 编译成 DZ 任务（或判定不可编译）
                ├────────────────►  DZ task (N, A, T, R)
                │                          │
                │                 ②DZ 训练/求解：MCTS + (p,v) + CE 策略迭代 + 自对弈
                │                          │ 终局/策略
                │                 ③证书编译 → Lean 证书 + 内核门（strict replay）
                │◄────── 证书/失败回退 ────┘
                ▼
   ④桥策略：AlphaProof 动作空间新增宏动作 dz(...)，学"何时调用"
```

四个部件：

1. **Extractor（Lean metaprogram）**：
   - 识别候选模式：`∃ x : FiniteType, Decidable P`；有限类型上的 `∀`；局部 `def` 为有限图/棋盘的结构；
   - 生成 `DzTask` 与一族证的 `checker_sound : 终局校验 → 原命题`；
   - 产出"可编译/不可编译"判定与置信度；不可编译返回原因（用于后续迭代）。
2. **DZ 训练/求解器**：
   - 自对弈（训练）与部署（推理）两用；可以托管在 `lmc` 风格的服务上（JSON Lines/HTTP，状态与动作都是小整数数组）；
   - 网络：定长 bit 输入 → `p ∈ Δ(N)`、`v ∈ R`；MCTS + 备份 + 软目标 CE。
3. **证书编译 + 内核门**：
   - 由终局生成 Lean 证书对象并组合成证明项；必须过严格复检（本项目已有 strict replay 基础设施）；
   - 失败即回退，不产生"近似正确"。
4. **桥策略（AlphaProof 侧）**：
   - 动作空间新增宏动作 `dz`（参数为 Extractor 生成的抽象 id）；
   - prover 学习**何时**调用（初始可用"Extractor 判定 + 尝试一次"的启发式冷启动，之后用结果反馈训练）；
   - 成功样本同时进入：AlphaProof 的 CE 数据、DZ 的自对弈/监督数据、Extractor 的触发分类器数据。

### 4.1 Lean 侧接口草案

```lean
-- 构造型任务的规格（示意；实际按族设计）
structure DzCtor where
  N     : Nat
  legal : (Fin N → Bool) → Fin N → Bool        -- legality mask
  reward : (Fin N → Bool) → Bool               -- 终局校验（同时是证书校验器）

-- 一族证一次的桥接定理：把"证书通过校验"变成原命题
theorem checker_sound (t : DzCtor) (s : Fin t.N → Bool)
    (h : t.reward s = true) : P s := by
  -- 每族一次的人工证明（或 decide）
  sorry
```

### 4.2 数据流与课程

- **矿工（0 GPU 先行）**：在现有 wave 日志/题库上批量跑 Extractor，统计可编译率，产出 `DZ-bench`；
- **课程**：按族（SAT、图证书、有限博弈……）分别训练；跨族不自动迁移（无免费午餐同款）；
- **吸收闭环**：`dz` 调用成功率反馈给 prover 触发策略；DZ 的 (p,v) 可蒸馏回 prover 先验（弱形态接口也可保留）。

## 5. 边界与坑（先钉死）

1. **表达力**：单调置位需要编码设计（一位一选择、mask、两方位域）；编码质量决定成败。
2. **"有限"≠"可解"**：`2^1000` 依旧爆炸；可解性来自结构（对称、局部、谱系）。无结构实例会输给专用求解器。
3. **不要替换完备求解器**：SAT/CP/MILP/`omega` 在其片段内已完备；DZ 的价值在**策略合成**（博弈/协议）与**启发式**（分支/编码选择）。
4. **证书忠实性**：Extractor 编码错误 → 编译失败（安全，但白干）；覆盖率取决于召回。
5. **奖励设计**：终局奖励 +（可证的）potential shaping；不要引入会改变最优策略的人工密集奖励。
6. **信任边界**：优先 `decide`/全证明 `checker_sound`，`native_decide` 仅作过渡（编译信任）。
7. **小样本统计**：小规模对照实验不要下显著性结论（见 `3-实验计划.md` §9）。

## 6. DZ-v0 实验规格（建议）

**目标**：验证"真 DZ"闭环（编译→自对弈→证书→内核门→收益）在至少一个族上成立。

| 阶段 | 成本 | 内容 | 交付 |
|---|---|---|---|
| DZ-v0a | 0 GPU，1–2 天 | Extractor 审计：在现有 wave/E2 证据/FATE/Pell 上统计可编译率；人工挑选 1 个族 | `DZ-bench` + 覆盖率报告 |
| DZ-v0b | CPU + 小 GPU 可选 | 实现 1 个族的 `DzTask` + `checker_sound`；小网络 + MCTS + 自对弈（可挂 `lmc` server）；证书编译进 Lean | 端到端 demo + 三指标 |
| DZ-v0c | 1 GPU-day | 接 `dz` 宏动作进 Reap 波次；测触发学习与吸收 | 对照报告 |

**指标**：

- Extractor 覆盖率（可编译目标 / 总目标）；
- 证书内核接受率（strict gate 通过率）；
- 同 Lean 预算增益（每 1000 次调用/每题预算 B 的解出差）；
- 自对弈效率（训练步数/墙钟 vs 解出率）；
- 吸收（加入 `dz` 后 generator 的泛化提升）。

**建议首族**（无现成求解器、证书有限、结构好）：

1. 有限博弈（n≤k 的棋盘/取石子变体）——最贴 AlphaZero 形态；
2. 小图着色/独立集构造——编码简单、证书直观。

## 8. 开放问题

1. 编码自动化：Extractor 能覆盖哪些 `Finset`/`Fintype`/`SimpleGraph` 形态？需要多少人工模板？
2. 规模边界：N<1000 下，哪类结构（对称/局部）仍可学？与专用求解器的交叉点在哪里？
3. 博弈型的对手建模与平局处理；双人值头结构与备份公式。
4. 证书大小与编译成本：策略表证书是否可接受（大小、`decide` 耗时）？
5. 触发学习：`dz` 的调用策略能否用**弱形态**网络（token 输入）站稳，再逐步替换为数值输入？
6. 与 disprove/反例管线（课程调度器）的对接。

## 附录 C：可编译清单（扩展）——形式语言 / 自动机 / 图灵机 / 元胞自动机 / 组合设计 / 类型论 / 程序验证

### C.0 先过一遍判据（六问）

```text
C1 证书有限？   证明义务能否归约为"∃ 一个有限对象"（赋值/迹/策略表/结构表）？
C2 参数有界？   时间、规模、半径、深度等无界参数是否都在题面里被界住？
C3 模拟廉价？   校验器/世界转移是否可执行、足以进 MCTS rollout（Lean 可 decide）？
C4 状态定长？   状态能否写成定长 bit / 小域向量 + legality mask？
C5 终局即证书？ 到终局能否直接用奖励函数校验，不需要再"说理"？
C6 非否定性？   若是 ∀ / 不存在 / 全局最优：先试着转成反例搜索；转不动就不适合。
```

满足 C1–C5 = DZ 候选；C6 决定能否只靠 DZ 收尾（收不了尾的、方向正确的部分仍可交给 AlphaProof）。

### C.1 形式语言与自动机

| 任务 | 证书 | 编码要点 |
|---|---|---|
| DFA/NFA 非空、交非空：找见证词 | 词 + 接受运行 | 控制状态 one-hot + 逐字符选择（或直接搜词） |
| 等价/包含的**反例** | 反例词 | 同上；正向证明需补集化+枚举（有限但更大） |
| DFA 辨识（≤k 态，与样本一致） | 转移表 | 状态=转移表位域；奖励=一致（+极小性） |
| CFG 歧义反例 | 两句法树 | 树编码；校验=同串不同树 |
| LTL/CTL 模型检验（有限 Kripke 结构） | 反例迹 | 状态=位置+轨迹；正向由不变式（见 C.6） |
| 自动机博弈 / 反应式合成（safety/reachability） | **位置策略表** | 无记忆策略 = 每状态一个选择 → 天然 bitboard |
| 奇偶博弈（小） | 带记忆策略 | 记忆规模有界 = 控制器位域 |

### C.9 总原则：构造有证书、普遍需证明

- **∃ / 构造 / 策略** → DZ 自带证书，可直接收尾；
- **∀ / 不存在 / 全局最优** → 先转反例搜索（DZ 找反例），或小规模"穷举+可判定证明"（`decide`）；
  转不动就交给 AlphaProof/数学。
- **部分可观测 / 连续 / 无界参数** → 不是 DZ 的范围。

### C.10 统一 Lean 接口模板（所有族共用）

```lean
-- 每族证一次：
theorem checker_sound (w : Witness) (h : check w = true) : P := ...

-- 实例收尾（DZ 提供 w）：
exact ⟨w, by decide⟩            -- 或
exact checker_sound w (by decide)
```

**扩张成本**因此只在两处：为该族写"校验器 + `checker_sound`"；其余（自对弈、MCTS、CE 更新、证书编译）所有族共用同一套模板。
