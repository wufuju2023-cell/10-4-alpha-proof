# 3 · 实验计划（E1–E8）

> 理论依据：`2-理论-多样性-可达性-吸收.md`。
> 前置上下文（先读哪些文件、数据在哪、环境怎么跑）：`4-实验前需了解的上下文.md`。
> 原则：先做**零成本、信息密度高**的实验（E2），拿到判据后再决定后续投入。

## 0. 总原则

1. **先诊断、后投入**：E2/E1 是诊断；E3–E8 是按判据分配的投入。
2. **配对与预算口径**：比较实验必须固定题集、seed、Lean 验证预算（或 token 预算），报告"每单位预算"的指标。
3. **统计功效**：40 题只够检测大效应；小效应实验先算样本量（见 §9），不要用单 seed、±1 题的差值下结论。
4. **heldout 卫生**：v009/v010 只在最终对照中评测，不用于调参；训练/调参用 v001 或独立切分。
5. **一切落盘**：日志、receipt、报告进 `reports/`；运行目录用 ext4（`~/lmc-run`），不放 gloway。

## E2 · 采样窗审计（先做：0 GPU，约 1 天）

> **状态：已完成（2026-10-07）** — 报告 `reports/e2-window-audit.md`，统计 JSON 同目录，脚本 `scripts/e2_audit_window*.py`。
> 结论摘要：44.9% 成功在窗内、55% 在窗边/窗外（k≤2）；selected 20 条中 11 条为稀有变体；logprob 尾部口径不可校准。

**问题**：搜索找到的成功战术，其先验 `p*` 分布是什么？多少落在采样窗内？多少是"搜索独有发现"（near-window discoveries）？

**数据**（全部已有，位置见 `4-实验前需了解的上下文.md` §2）：
- `training_initial_evidence_20261006.zip` → `remote/tmp/fate-m-formal-w001-shared-rollout-v2/_actor_receipts/fate_m_XXX_v001/policy_requests/*.json`（每次策略请求的候选与 logprob）；
- 同包内 `<problem>/observer.jsonl`（generation/eval 事件流，含 `raw_logprob`）；
- `training_initial_evidence_20261006.zip` → `runs/formal-20x10/wave_001/ce/update/replay/transitions.jsonl`（20 条选中 transition）；
- `join_v2_evidence_20261006.zip` → `joins/…/strict-replay/receipt.json` 与 `online-v2-receipts.json`（49 条严格成功）。

**步骤**：
1. **解剖一个 receipt 文件**，确认字段口径：候选列表、logprob 是序列级还是 token 级、采样参数（写进报告，避免误解）。
2. 抽取所有 `(problem, state, tactic, logprob)`；标记执行结果（ok/invalid）与验证结果（严格成功/失败）。
3. 计算每题/每节点实际预算 `B` 与窗口 `θ_B(δ=0.1)`。
4. 统计：
   - 成功战术的 `−log p*` 分布（中位数、分位数）；
   - `P(p* ≥ θ_B)`（在窗口内的比例）；
   - **"搜索独有发现"占比**：成功但 `p*` 接近/低于窗口的战术比例；
   - 对照：失败战术（invalid/timeout）的先验分布。

**判据（决策树）**：
```text
多数成功 p* ≥ θ_B          → 瓶颈在"排序"：投值函数 / 数据规模（E3 重点测值函数）
相当比例成功 p* ≈ θ_B      → 瓶颈在"发现"：投采样宽度 / 族覆盖 / 检索（E1/E4/E7）
存在 p* < θ_B 的成功       → 先查语义去重与 logprob 口径（可能是记录问题或幸运样本）
```

**交付**：`reports/e2-window-audit.md` + 统计 JSON。

## E1 · 语义多样性审计（1 GPU-hour + CPU）

**问题**：模型对同一状态采样的 `K` 个候选，经 Lean 执行后还剩多少**语义**多样性？温度、模型版本如何影响它？

**方法**：
1. 取一批固定状态（建议：Pell 冒烟题的中间状态 + FATE v001 若干题的中间状态，约 20–50 个）。
2. 对每个状态采样 `K = 32 / 64`（温度 `T ∈ {0.7, 1.0}`）。
3. 每个候选经 lmc server 执行（一次 `apply`），记录：执行成功 / 结果状态 `state_key` / 战术族头部（解析首个 token：`intro/cases/induction/simp/rw/apply/…`）。
4. 计算：`D_sem = #distinct state / K`、`D_fam = #distinct head / K`、进展率（成功执行的候选比例）、`state_key` 为空的失败率。

**无 GPU 降级**：直接解析 evidence 里已有的 `policy_requests` + `observer.jsonl`（候选是当时采样的），做"历史多样性"近似——质量低（状态上下文不全），但零成本。

**判据**：
- `D_sem` 低（如 < 30%）：多样性是当前瓶颈 → E4（族覆盖）优先级最高；
- `D_sem` 高但搜索没提升：瓶颈更可能在排序/吸收 → 转 E3/E5。

**交付**：`reports/e1-diversity-audit.md`。

## E3 · 搜索 vs 采样：同预算对照（1 GPU-day）

**问题**：MCTS（±值函数）相比 best-of-B 独立采样，在**同 Lean 预算**下多解出多少题？——直接度量 C2 的"搜索提升"。

**方法**：三臂实验，同一题集（建议 FATE v001 全 20 题起步，后续扩到更大切分）、同一初始模型、同一 Lean 预算 `B`（如 64 / 256 次验证/题）：

| 臂 | 描述 |
|---|---|
| (a) best-of-B 采样 | 从策略独立采样，逐条执行/验证，首次成功即止 |
| (b) MCTS + 值函数 | 对齐超参配置（τ=200、K=6、c_AND=64…） |
| (c) MCTS − 值函数 | 纯先验 + 环境反馈（Q 用 0 或剩余步数启发式） |

**指标**：每题解出（严格成功）；**每 1000 次 Lean 验证的解出数**（预算归一）；配对差值。
**记录**：`p*` 分布（复用 E2 工具）、树规模、replay 规模。

**判据**：
- (b)−(a) ≈ 0：搜索在当前模型/预算下不值得 → 转投数据规模与外化（E7），搜索保持离线；
- (b)−(a) 显著且 (b)−(c) 显著：值函数在起作用 → 扩预算、优化值头；
- (b)−(a) 显著但 (b)≈(c)：提升来自"多步组装"而非值函数 → 检查 MCTS 预算分配。

**交付**：`reports/e3-search-vs-sampling.md`。

## E4 · 族覆盖提议（机制改动 + 0.5 GPU-day）

**问题**：把提议分解为"有限族 × 族内生成"，能否恢复部分多样性保证并提升搜索？

**方法**：
```text
π(t|s) = Σ_{f∈F} w_f(s) · π_θ(t | s, f)
```
- 族 `F`：从战术头部定义（`intro / cases / induction / simp / rw / apply / exact / constructor / …`，约 10–20 个）；
- `w_f`：先均匀（强制覆盖），再试 PUCT 权重；
- 实现：对每个采样 batch 按族配额分配 `K` 个候选（或 prompt 条件化 + 重加权）。

**指标**：`D_fam`、`D_sem`、解出率、每族利用率（有效候选比例）。
**对照**：vanilla 采样（同预算）。

**判据**：`D_fam` 上升且解出率不降 → 采纳为默认提议结构；若解出率下降 → 强制覆盖引入太多弱候选，改软配额。

**交付**：`reports/e4-family-coverage.md`。

## E5 · 软目标 vs 路径 CE（1 GPU-day）

**问题**：用"访问分布（软目标，含失败比较信息）"蒸馏，是否比"只模仿选中路径（硬目标）"吸收更好？

**方法**：同一批搜索产物，两种目标各训一版（其余完全一致：LoRA 秩、学习率、SFT 混比、数据量）：
- (a) 现状：选中路径 CE；
- (b) 软目标：以候选访问分布为目标（需导出每次扩展的候选与访问计数；检查 `raw_tree.json`/observer 是否够用，不够则在 v1 搜索里加导出）。

另加秩扫描：`r ∈ {8,16,32,64}` 各一版，测吸收饱和度。

**指标**：训练集重解率、同族迁移（用 v001 训练后测 v009/v010 的净增——一次性评测，不调参）、回放集保持率（旧能力退化）。

**判据**：软目标在迁移/保持上占优 → 改造 `update_offline` 目标；两者持平 → 先解决数据规模问题。

**交付**：`reports/e5-soft-vs-hard-targets.md`。

## E6 · 释义增广 + 保持（0.5 GPU-day）

**问题**：CE 学到的是"策略"还是"token 序列"？

**方法**：
1. 对成功轨迹做安全变换：假设改名（`h` → `h₁` 等）、无关假设重排、goal 包装微调，得到释义样本（变换后必须过 Lean 严格验证，保持语义）。
2. 对照训练：(a) 原样本；(b) 原样本 + 释义增广。
3. 评测：原名状态与改名状态的解出率差；回放集保持。

**判据**：对改名显著敏感且增广改善 → 目前主要在学习 token 表面形式，需要增广/结构正则；不敏感 → 泛化能力尚可，转向数据规模。

**交付**：`reports/e6-paraphrase-robustness.md`。

## E7 · 外化：引理库 + 检索 + 工具战术（工程 + 1 GPU-day）

**问题**：把"事实记忆"外化（引理库/检索/决策过程工具）后，同参数、同预算下解出率能否上升？

**方法**：
1. **引理库**：从搜索与验证过程中收集已验证的中间引理（`have` 子句、成功子目标）；建索引（先 BM25/字符串，后 embedding）。
2. **检索条件化**：提议时注入检索到的引理（prompt 或 premise 列表），统计命中率与引用率。
3. **工具战术**：统计并鼓励决策过程（`norm_num / omega / linarith / decide`）——把无限动作空间压向"有限工具集 + 参数"。

**指标**：检索命中率、引用后成功率、同预算解出率、成功战术 `−log p*` 的下移幅度。
**判据**：显著且成本可控 → 成为主线组件；不显著 → 回到数据规模路线。

**交付**：`reports/e7-externalization.md`。

## E8 · 课程闭环（长期）

**问题**：用"前沿"（搜索能解、贪心解不出）选题，能否把"搜索改进"转化为持续泛化（AlphaZero 自对弈的类比）？

**方法**：
1. 每波开始前，用当前策略 + 小预算搜索给题库打标：`greedy 可解 / search 可解 / 都不可解`。
2. 优先选择"search 可解且 greedy 不可解"的前沿题进入训练波。
3. 用现有 FATE 变体基础设施（20×200）扩展题目分布；记录前沿位置随波次的移动。

**指标**：前沿集合的规模与难度位置随波次变化；Heldout 解出数 vs 波数曲线；`D_sem` 与输出熵的波次曲线（防坍缩）。
**判据**：前沿持续右移且 heldout 上升 → 泛化闭环成立；前沿不动或坍缩 → 课程设计失败，回到 E5/E6。

**交付**：`reports/e8-curriculum-closure.md`（长期滚动）。

## §9 统计功效备忘

- 40 题、单 seed：只能检测"净增 ≥ 5 题"级别的效应（粗略：`σ ≈ √(p(1−p)/n)`，`n=40`、`p≈0.6` 时 `σ ≈ 0.078`，95% 置信区间半宽约 ±0.15 ≈ ±6 题）。
- 要检测 ±1 题（±2.5pp）：需要 `n ≈ 1500`（粗略），或换成**配对指标**（同题前后差）并接受更大不确定性。
- 结论：小效应实验（E5/E6）先用"净增/净减 + 置信区间"表述，不做显著性声称；大效应实验（E3）可以 20 题起步。
