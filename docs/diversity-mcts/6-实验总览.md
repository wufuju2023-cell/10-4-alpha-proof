## 1. E2 · 采样窗审计

**问题**：搜索找到的成功战术，其采样先验落在哪里？多少是"搜索独有发现"？

**数据**：FATE-M v001 证据包（20 题 / 1280 raw draw / 233 canonical / 49 verified；zip 哈希见报告）。

**关键数字**：

- 窗内（`k/64 ≥ θ_B = 3.6%`，即 k≥3）：**22/49 = 44.9%**；窗边/窗外（k≤2）：**27/49 = 55.1%**；单次发现（k=1）：20/49。
- 同预算（64）重发现概率：k=1 ≈ 63%；k=2 ≈ 87%（MLE 近似）。
- CE 实际使用的 20 条 selected：**11 条 k≤2（9 条 k=1）**；选择规则 = first-verified（与频率无关，20/20 可复现）。
- **高频 ≠ 正确**：`exact curry_target` 出现 44 次全部失败；k≥20 的 22 条样本仅 4 条成功。
- 记录 logprob 尾部不可校准（f009：`p_model=8e-8` 却真实出现 1 次）→ 窗口分析改用**经验频率 k/64**（右删失已注明）。

**判据结论**：**"发现瓶颈"分支成立** → 按计划投采样宽度 / 族覆盖 / 检索（E1/E4/E7）。

## 2. CPU-1 · HTPS 式"最小证明选择"重排

**背景**：HTPS（arXiv 2205.11491）用"最小证明树"选训练样本；我们现状是 first-verified。用现有 49 条 verified 离线重放五种选择规则。

| 规则 | 平均重发现 | 选中 k=1 的题数 | Σk |
|---|---:|---:|---:|
| R0 first（现状） | **0.823** | **9** | 173 |
| R1 maxk | **0.975** | **1** | 258 |
| R2 mintok（最短战术） | 0.938 | 3 | 236 |
| R3 minchar | 0.919 | 4 | 219 |
| 均匀随机（期望） | 0.894 | 4.9 | 206 |

- **first-verified 低于均匀随机**；机制：评估顺序 ≈ survivor 序号降序，而 `Spearman(survivor, k) = −0.80` → 结构性偏爱最稀有变体（选中者 survivor 分位恒为 1.00）。
- 建议（详见报告 §7）：选择规则改 **max-k**（tie 用 token 长度）；多步题把最小性升级为**总步数 / 总 CPU 时间**。
