## 简短结论

**没有保证，而且"不同战术是否真的不同"在语法层面根本无法保证。** 官方解法不是去判定战术是否不同，而是把"不同"操作化成了两条合并规则：**同战术字符串 → 先验累加；同结果状态 → 合并分支**。真正被 MCTS 当作"动作"的是**动作的效果（子状态）**，战术字符串只是提议的标签。

## 为什么没有保证（三个层次）

1. **语法不同 ≠ 语义不同**：`exact rfl` 与 `rfl`、`assumption` 与 `exact h`、`simp` 的两种写法——字符串不同，语义完全一样。
2. **战术不同 ≠ 子状态不同**：两个不同的战术串可能产生同一个 proof state（goal 列表相同），甚至一个战术是另一个的"冗余包装"（`intro x` vs `intro x; skip`）。
3. **同战术 + 同状态 → 结果基本确定**：环境冻结、无随机性，且 `?` 结尾的探测类战术（`apply?`/`simp?`）和 `sorry/admit/repeat'` 都被 `checkTacticSyntax` 禁掉了。所以"不确定性"只存在于第 2 条，而它无法靠字符串判定。

## 官方的操作化处理（Reap 与我们的实现一致）

Reap `TreeSearch.lean::visitNode` 里新增候选战术时的合并条件是：

```lean
-- 同战术字符串（先验累加） 或者 同子状态 key（合并节点）
find? fun ((e, c), _) => e.tacticStr == t || c.key == childData.key
```

我们 Python MCTS（`lmc/mcts.py`）逐字对齐了这两条：

```python
if action in node.children:        # ① 同战术 → 先验累加（官方 expand_node）
    node.edges[action].prior += prior; continue
res = self.session.apply(node.state, action)
dup = next((k for k, c in node.children.items()
            if c.state_key == res.state_key), None)
if dup is not None:                # ② 同结果状态 → 合并（不管战术串是否相同）
    node.edges[dup].prior += prior; continue
```

`state_key` 就是对 goal 做 pretty-print 后的 JSON（Reap `stateKey`，我们服务端同款）。这就是那个"保证"的替代品：**不去证明战术不同，而是用状态等价把重复效果合并掉。**

## 为什么状态级去重才是对的（和 AlphaZero 的对照）

- AlphaZero：动作 = 棋盘坐标，**规范有限**，且"不同动作 → 不同局面"由规则天然保证；所以它不需要状态去重，多样性直接来自 PUCT + 固定动作集上的噪声。
- Proving：动作空间无穷（战术语言），每次扩展的"动作集"其实是 **policy 现场采样的 K=6 个候选**；而搜索具有马尔可夫性——**未来的选择只依赖 proof state，不依赖你是用哪条战术走过来的**。因此"MCTS 真正在搜的是状态图（可合并的 DAG），战术只是边上的标签"。
- 所以在这个问题里，"多样性"的正确粒度是**子状态多样性**，不是战术串多样性。去重不但不损害多样性，反而把原本会浪费在等价分支上的访问量集中起来——**提升每次 visit 的有效多样性**。

## 这个近似的边界（重要）

- pp-based 状态键是**启发式**：hypothesis 改名（`rename_i`/不同 intro 名）会漏合并；而隐藏的 mctx 差异（pp 不显示的信息）可能被误合并。
- 误合并**只损失完备性机会，不影响可靠性**：最终证明由内核复验兜底（我们的 `verify` = 重放 + `checkProof`；wrong merge 最多浪费一个候选，不会产出假证明）。
- Reap 还有 `ancestorKeys` 防环（同状态不重复出现在自己的祖先链上）；我们的 v0 **还没实现这条**，重复采样"无进展战术"（如快速失败的 `simp` 变体）目前只由 `max_nodes/max_steps` 限制，建议下一版补上。
- 还有个反直觉的官方设计：**同战术被采样多次时先验是"累加"的**（越常被采到越有质量），而不是去重降权——这是 `expand_node` 的官方语义，我们保留了。

## 多样性实际来自哪里（现行配置）

`K=6` 采样 × 每状态多次扩展（渐进采样：`n_eval ≤ 0.01·n^0.6` 才停止重扩展，只增不减）× 先验温度 `τ=200`（logprob/200 后先验接近均匀，探索项主导）× PUCT 的 `c_base=3200`。再加上状态去重，保证"预算花在真正不同的状态上"。

**一句话**：alpha-zero 里动作的"不同"由棋盘规则保证；Lean 里没有这种保证，官方用"同串合并先验 + 同状态合并分支"两个安全网近似它，正确性交给内核，效率交给采样与探索——这正是我们从第一天起就在会话协议里带上 `state_key`、并复刻两条 dedup 规则的原因。
